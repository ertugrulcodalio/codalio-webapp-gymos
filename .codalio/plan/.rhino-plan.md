# Implementation Plan: GymOS

## Summary
GymOS is a robust, multi-tenant SaaS platform designed for gym owners to manage operations, plans, and bookings under their own brand/subdomain, and for members to view active plans, available classes, and manage bookings without cross-tenant data leakage.

## PRD gaps compensated
- **PRD_PROTOTYPE_ROUTE_GAP**: Added custom route and page for gym owner registration at `/register` on the main domain.
- **SITEMAP_PAGE_NO_AC**: Created a dashboard overview page for staff at `/staff/dashboard` showing key metrics and quick actions.
- **DATA_MODEL_UX_MISMATCH**: Defined a `Transaction` model to track active member plans, billing history, and mock payments.
- **PROTECTED_ROUTE_NO_AUTH_AC**: Enforced `gym_staff` role check on all staff routes and redirect unauthenticated users to `/staff/login`.

## Models (reference)

### Trainer
- Ownership: organization-scoped
- Key fields: name, bio, email
- Relationships: belongs_to :organization, has_many :gym_classes

### MembershipPlan
- Ownership: organization-scoped
- Key fields: name, price, status, weekly_class_limit
- Relationships: belongs_to :organization, has_many :member_profiles

### GymClass
- Ownership: organization-scoped
- Key fields: name, description, start_time, end_time, capacity, status
- Relationships: belongs_to :organization, belongs_to :trainer, has_many :bookings

### Booking
- Ownership: organization-scoped
- Key fields: user_id, status, gym_class_id
- Relationships: belongs_to :organization, belongs_to :user, belongs_to :gym_class

### MemberProfile
- Ownership: organization-scoped
- Key fields: user_id, status, membership_plan_id
- Relationships: belongs_to :organization, belongs_to :user, belongs_to :membership_plan

### Transaction
- Ownership: organization-scoped
- Key fields: amount, plan_name, status, user_id
- Relationships: belongs_to :organization, belongs_to :user

## Extras (NOT covered by blueprint — develop stage implements these by hand)

### Weekly Class Limit Enforcement (Booking#create)
- **Model + action**: `Booking#create`
- **Rule**: A member cannot book a class if they have already reached their membership plan's weekly class limit for the current calendar week.
- **Where the code lives**: `app/policies/booking_policy.rb`
- **Acceptance criterion**: AC-61 (Enforce Weekly Class Limit)

### Class Capacity Validation (Booking#create)
- **Model + action**: `Booking#create`
- **Rule**: A member cannot book a class if the class is already at full capacity.
- **Where the code lives**: `app/models/booking.rb`
- **Acceptance criterion**: AC-53 (Book a Class capacity validation)

### Trainer Availability Validation (GymClass#create / GymClass#update)
- **Model + action**: `GymClass#create` / `GymClass#update`
- **Rule**: A trainer cannot be assigned to a class if they are already scheduled for another class at the same time.
- **Where the code lives**: `app/models/gym_class.rb`
- **Acceptance criterion**: AC-35 (Trainer availability validation)

### Prevent Deletion of Active Plans (MembershipPlan#destroy)
- **Model + action**: `MembershipPlan#destroy`
- **Rule**: A membership plan cannot be deleted if there are active member subscriptions (member profiles) associated with it.
- **Where the code lives**: `app/models/membership_plan.rb`
- **Acceptance criterion**: AC-30 (Prevent deletion of plans with active subscriptions)

### Prevent Deletion of Active Trainers (Trainer#destroy)
- **Model + action**: `Trainer#destroy`
- **Rule**: A trainer profile cannot be deleted if they have active classes assigned.
- **Where the code lives**: `app/models/trainer.rb`
- **Acceptance criterion**: AC-24 (Prevent deletion of trainers with active classes)

## Implementation order (recommended stage flow)

1. **Plan** — This artifact set (YAMLs, plan, criteria, index).
2. **Develop** — Phase A: `bundle exec rails agentcode:blueprint` + migrations. Phase B: implement **Extras** (custom validations and policies). Phase D: write backend unit + integration tests for every AC.
3. **UI / UI-Integration** — Build screens listed above; `ui-integration` adds Cypress for the critical flows.
4. **Test** — Run `bundle exec rails test` to confirm green and tighten anything broken.
5. **Review** — PRD compliance + test/coverage report.
